# Corey Phillips puzzle: oracle implementation report

## Scope and safety boundary

Phase 4 implements only a deterministic, local, single-candidate address
checker. It does not implement candidate generation, wordlist ingestion,
iteration, concurrency, GPU support, network queries, key export, signing, or
transaction construction. No brute-force search or real-candidate enumeration
was performed.

Files:

- `tools/corey_oracle.py`
- `tests/test_corey_oracle.py`
- `research/corey/unicode-compatibility.md`
- this report

## Exact implemented pipeline

For one literal passphrase `P`, the normative path is:

1. read the committed kitten JPEG as exact bytes;
2. RFC 4648 base64-encode those bytes with no data-URI prefix or line wrapping;
3. SHA256 the base64 bytes to obtain 256-bit BIP39 entropy;
4. append the eight-bit BIP39 checksum and split into 24 11-bit indices;
5. map the puzzle's 24 verified English indices to its mnemonic;
6. NFKD-normalize both mnemonic and `P`, then UTF-8 encode them;
7. run PBKDF2-HMAC-SHA512 with password `mnemonic_utf8`, salt
   `b"mnemonic" + passphrase_utf8`, 2048 iterations, output length 64 bytes;
8. run BIP32 private derivation at `m/84'/0'/0'/0/0`;
9. serialize the final secp256k1 public key in compressed SEC1 form;
10. calculate RIPEMD160(SHA256(pubkey));
11. encode that 20-byte witness-v0 program as mainnet Bech32; and
12. compare the resulting address exactly with
    `bc1qcyrndzgy036f6ax370g8zyvlw86ulawgt0246r`.

The target decodes locally to HRP `bc`, witness version 0, and 20-byte program
`c1073689047c749d74d1f3d071119f71f5cff5c8`.

## Error and output contract

The API result is one of `MATCH`, `NO_MATCH`, or `ERROR`. Invalid Unicode input,
unsupported modes, malformed paths, unavailable RIPEMD160, invalid BIP32 keys,
and Bech32 failures are errors, not negative matches.

The command line accepts either `--selftest` or exactly one positional
candidate. There is no batch input or search flag. Normal output contains only
the verdict. `--debug` adds candidate and seed hashes plus public derivation
artifacts; it does not print the passphrase, mnemonic, seed, or any private key.

## Independent self-test design

The self-test does not merely compare current output with values generated by
the same implementation. It has three provenance classes:

| Class | Checks | Independent anchor |
|---|---|---|
| Public protocol vectors | BIP39 seed, BIP32 master and hardened child, secp256k1 compressed generator, BIP173 P2WPKH encode/decode | Constants copied from published specifications/vectors |
| Puzzle reconstruction | raw image digest, base64-derived entropy, checksum-bearing word indices, mnemonic, empty-passphrase seed digest, master fingerprint, final public key, HASH160, sister address | Recomputed from the committed image and compared across intermediate layers |
| Target structure | Bech32 checksum, HRP, witness version, program length and bytes | Target address decoded independently of candidate derivation |

This catches different fault classes: image drift, wrong base64 rules, mnemonic
checksum/index errors, absent NFKD, PBKDF2 errors, BIP32 path errors, elliptic
curve serialization errors, HASH160 errors, and Bech32 errors.

There remains a limit: the implementation is a small in-repository reference,
not yet compared end-to-end with a second independently maintained wallet
library on this exact puzzle fixture. That comparison is required before the
oracle can be trusted for real search.

## Unicode and historical compatibility

The standard path applies NFKD to both BIP39 inputs. A separate opt-in
`raw-compat` mode models direct UTF-8 encoding and is covered only by synthetic
Unicode tests. The original 2019 dependency versions could not be established,
so this mode is explicitly unverified and must not be silently mixed with the
standard path. See `research/corey/unicode-compatibility.md`.

## Mnemonic and input provenance

Status: **RECONSTRUCTED**, not independently confirmed by a second tool.

The committed JPEG is read at self-test time. Its raw SHA256 and the SHA256 of
its exact base64 encoding are recomputed; the resulting entropy plus checksum
is split into 24 word indices. Those indices are matched to the 24 required
entries from the official English BIP39 list without committing a duplicate
2,048-word list. The resulting sentence is then used for the empty-passphrase
derivation. The test therefore fails if the image, encoding rule, checksum,
indices, mnemonic, path, or any public downstream artifact drifts.

## Validation performed

Only bounded validation was run:

```text
python3 -m unittest -v tests/test_corey_oracle.py
python3 tools/corey_oracle.py --selftest
```

Exact successful result: 13 tests ran and returned `OK`; `--selftest` returned
`PASS` for `bip39_nfkd`, `bip32`, `secp256k1`, `bech32_p2wpkh`,
`puzzle_reconstruction`, and `target_structure`.

The suite uses official fixed vectors, the empty
passphrase sister-wallet control, one repeated synthetic determinism value, and
one synthetic CLI redaction value. These calls are test fixtures, not a
candidate list or search. All tests and all six self-test groups pass.

## Known limitations and unresolved assumptions

- No second independently maintained implementation has reproduced the complete
  puzzle fixture end to end.
- The archived/deployed 2019 JavaScript dependency versions and exact Unicode
  behavior remain unknown.
- The sparse 24-entry word-index fixture checks this puzzle without duplicating
  the full BIP39 English list; the official BIP39 seed vector separately checks
  the standards derivation.
- RIPEMD160 availability depends on the Python runtime's `hashlib` provider; its
  absence produces `ERROR`, never `NO_MATCH`.
- The fixed BIP32 path is assumed from the sister-address reconstruction and
  prior research. No path alternatives are exposed by this oracle.

## Gate decision

- Oracle implementation readiness: **GO (complete)**.
- Oracle verification for real search: **NO-GO**.
- Solver/search: **NO-GO**.

Phase 5 is blocked on an independent end-to-end implementation reproducing the
image-to-mnemonic pipeline and the empty-passphrase sister address, plus a
resolved decision on whether non-ASCII historical compatibility needs testing.
Until those conditions are met, no real candidate should be submitted to this
oracle and no generator or brute-force process should be built.
